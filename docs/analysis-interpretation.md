# Самостоятельный разбор ответа анализа

Первый шаг плана выполнен 13.10.2026 в `speech-backend`: проверка и
интерпретация одного ответа LLM выделены из обработчика конвейера.
Сервис использует `AnalysisExecutionService` в CPU-процессе бэкенда.
Приём и доставка ASR уже реализованы; LLM-ответы из воркера не передаются.
Совместимый старый обработчик удалён 14.10.2026.
[Главное правило](processing-ownership.md).

## Вход и выход

`AnalysisInterpretationService.interpret()` принимает
`AnalysisInterpretationRequest`:

- `outputs` — JSON-совместимый выход модели. Поддерживается разобранный объект
  либо текст JSON в `answer`, `text` или `output`.
- `context.classifier` — Pydantic-снимок узлов дерева, включая выключенные;
  `ClassifierIndex` исключает выключенные узлы вместе с их потомками.
- `context.needs_roles` — запрашивались ли роли для этой расшифровки.
- `context.reason_codes` — именно коды причин, которые были отправлены модели.

DTO запрещают переназначение полей; лишние поля контекста и запроса запрещены.
Сырой ответ исключён из `repr` запроса. Текстовые обёртки и блоки `<think>` читаются
общим JSON-помощником, который продолжает использоваться оценкой.

Результат — прежний `AnalyzeWork`: найденный узел и путь, тональность,
резюме, сегмент/продукт, допустимые роли, предложение темы и причина.
Его поля, значения по умолчанию и сериализация сохранены. Модель принадлежит
domain и переэкспортируется через DTO application; вторую копию её полей
не создаём. Старый импорт из `application/dto/pipeline.py` остаётся доступен.

Сервис не обращается к БД, модели, очереди или настройкам. Он не кеширует
классификатор: каждый запрос применяет переданный снимок. Контекст формирует
`AnalysisExecutionService` по данным репозитория и фактически отправленным
модели справочникам. HTTP-версия и внешняя авторизация здесь пока не вводятся.

## Сохраняемые правила

- Обязательны список `path` хотя бы с одной непустой строкой и одно из
  трёх известных значений тональности. Неправильную тональность не заменяем
  на `neutral`.
- Путь сверяется с деревом; неизвестная ветка сохраняет только найденные
  уровни. Модель не создаёт новые узлы.
- Предложение темы необязательно. Полностью найденное предложение получает
  узел и подписи дерева; собственная формулировка остаётся словами.
- Резюме ограничено 300 символами, подпись уровня предложения — 120.
  Пустые подписи, прочерки и «(пусто)» сохраняют прежнюю обработку.
- Роли применяются только при `needs_roles=true`; ошибочный элемент
  пропускается. Известные роли по аудиоканалам не заменяются ответом модели.
- Причина берётся только при наличии отправленного справочника.
  Неизвестный код не сохраняется; отсутствие причины не отменяет анализ.

## Отказы и конвейер

Пустой ответ, оборванное рассуждение, непрочитанный JSON и неправильная
обязательная форма дают `InvalidAnalysisOutput`. Сообщение описывает
проблему без содержимого ответа и значений неизвестной тональности.

`AnalysisExecutionService` ловит этот отказ и сохраняет предел трёх ответов
внутри одной попытки задания. После исчерпания возвращается `INVALID_OUTPUT`.
Ошибки HTTP/провайдера по-прежнему получают классы очереди; самостоятельный
сервис их не обрабатывает. CPU-сценарий сохраняет результат через порт
атомарной транзакции: снимок, nonce, done и снятие прежней оценки проверяются вместе.

Заполнение причин использует общие функции чтения из `analysis/output.py`,
а не импортирует разбор из обработчика конвейера. Сравнение моделей вызывает
`AnalysisExecutionService` на одном DTO входа для обеих моделей без записи результата.
