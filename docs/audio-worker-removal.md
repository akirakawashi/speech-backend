# Удаление старого аудиоворкера из бэкенда

Выполнено 14.10.2026 по решению владельца. После выделения `speech-worker`
в бэкенде оставался второй исполнитель получения и распознавания записей.
Его потребители проверены и удалены. Обработка аудио теперь реализована
только в проекте воркера. Сервер ещё не переключён.

## Что удалено

| Прежний потребитель | Результат |
| --- | --- |
| `presentation/cli/worker.py`, `di/worker.py`, `di/pipeline.py` | Старую команду общего конвейера больше нельзя запустить из бэкенда |
| `application/pipeline/` | Удалены обработчики ingest/ASR и совместимые обёртки анализа/оценки; CPU-сценарии уже используют собственный runtime |
| `infrastructure/queue/worker.py`, `resources.py` | Удалён второй цикл выполнения этапов; PostgreSQL-очередь для CPU и администрирования сохранена |
| Клиент Whisper, `infrastructure/transcription/`, `infrastructure/media/` | Удалены multipart ASR, ffmpeg/ffprobe, временные аудиокаталоги и их порты/DTO |
| Потоковые скачиватели NCC/Телфина, `build_worker_source`, маршрутизация и файловый адаптер MinIO | Адаптеры источников бэкенда перечисляют только метаданные |
| `SpeechAudioStorage.put` | Бэкенд больше не загружает оригиналы записей в MinIO |
| Цель Dockerfile `speech-worker` | В бэкенде нет сборки аудиоворкера и установки ffmpeg |
| Параметры модели, языка, VAD, ключа и таймаута `SPEECH_WHISPER_*` | Удалены из Settings и шаблона; рабочие `.env` сохранены |

Порт LLM теперь расположен в [application/ports/analysis.py](../src/application/ports/analysis.py).
Общий нормализованный отказ CPU-сценариев — в
[application/errors/stages.py](../src/application/errors/stages.py).
Старую структуру `application/pipeline` ради этих двух типов не сохраняем.
Зависимости UV не сократились: HTTP, SQLAlchemy и Pydantic используются
действующими сценариями. Lock-файл сохраняет прежние версии.

## Что осталось действующим

- `speech-process` и `speech-analyze`: CPU-анализ/оценка через
  [JobProcessor](../src/infrastructure/runtime/job_processor.py) и порты
  атомарной записи с проверкой снимка, nonce и аренды.
- `speech-ingest`/`speech-backfill`: метаданные, история, допуск и приоритеты.
  NCC `sequence` использует HEAD для даты/наличия записи без её тела;
  `reporting_view` больше не требует REST-клиента и его секретов.
- Служебные `ingest/prepare`, `ingest/resolve` и `transcription-results`:
  первый путь выдаёт бизнес-решения, второй атомарно принимает ASR.
  Их DTO, токен, правила повторов и квитанции не менялись.
- SQL чтения ingest, сохранения расшифровок, анализа и оценки: его вызывают
  действующие репозитории. Удалены только прежние обёртки записи по ClaimedJob.
- MinIO: чтение/Range для проигрывания аудио, HEAD для проверки состояния,
  удаление для сохранённой команды хранения. Оригиналы не удалялись.
- API, ORM-регистрация, миграции, команды LLM, справочников и хранения.
  При удалении использовалась `sp_0016_evaluation_jobs`, пользовательский API — 3.0.
  Последующая добавочная миграция анализа — `sp_0017_analysis_storage`;
  [порядок перехода](analysis-storage.md).

`SPEECH_WHISPER_BASE_URL` оставлен намеренно: панель конвейера выполняет
необязательный `GET /models`. Это проверка доступности, а не распознавание;
ключ Whisper и остальные параметры ASR нужны только воркеру. При пустом
адресе панель показывает «не настроено». Compose по-прежнему не передаёт
этот необязательный адрес. Рабочий `.env` со старыми ASR-полями загружается:
неизвестные поля игнорируются через `extra="ignore"`.

## Проверка потребителей и тесты

Проверены CLI, DI, зарегистрированные HTTP-роутеры, CPU-runtime, адаптеры
источников, SQL-репозитории, Dockerfile, Compose и установленный пакет.
Исходные старые проекты не менялись. В `local-dev` обновлена только ветка
нового бэкенда: worker запускается из отдельного проекта, `themes.sh` использует
`speech-analyze`, `all.sh` запускает API до аудиоворкера. Прежние режимы сохранены.
Переключение сервера требует отдельного выпуска согласованной пары проектов.

Проверки аудиоподготовки, Whisper, таймкодов, скачивания, безопасных отказов
и технического цикла удалены из бэкенда вместе с дублирующей реализацией:
они уже есть в самостоятельном `speech-worker`. Бизнес-проверки анализа,
снятия оценки, SQL, приёма суток, отсрочек и административной переобработки
сохранены на действующих сценариях. Приём ASR проверяется через HTTP и
настоящую PostgreSQL, включая замену текста, следующий этап, отказ commit,
повтор, устаревший nonce и изменение входа.

До удаления прошли 222 целевых теста на отдельной PostgreSQL; после удаления
прошли 386 проверок сохранённых сценариев и адаптеров. Полные наборы с
`SPEECH_REQUIRE_LIVE_PROOFS=1` на временной PostgreSQL после миграций:
бэкенд — 1374 passed, 21 skipped; воркер — 379 passed. Пропущены только
проверки отсутствующих внешних скриптов инфраструктуры. Ruff, форматирование,
строгий mypy и `uv lock --check` прошли в обоих проектах. UV собрал wheel/sdist;
Docker собрал API, CPU, миграции и воркер.

Установленные пакеты проверены вне исходников под UID 10001: 11 команд
бэкенда и 3 воркера, отсутствие удалённых модулей и ffmpeg в бэкенде.
Один сквозной прогон отдельных контейнеров прошёл путь
«повторный приём → ingest → ffmpeg → Whisper → API ASR → CPU-анализ»:
настоящие HTTP и PostgreSQL, синтетическое аудио, подставные S3/Whisper/LLM.
Все задания завершились; LLM вызывал только CPU-процесс. Это не проверка
качества и доступности живых моделей.

Проверены синтаксис Bash, настоящие `--help` нового воркера/анализа и
изолированный запуск `local-dev` с подставными командами: окружения разделены,
API запускается до воркера и используется повторно. Тестовые контейнеры и
синтетические аудиофайлы удалены. Рабочие `.env`, базы, исходные проекты и
действующие службы не менялись. [План и следующие задачи](refactoring-plan.md).

## Что дальше

1. Перенести решения синхронизации справочников и срока хранения из воркера
   в бэкенд. Техническое удаление по готовой команде может остаться в воркере.
2. Проверить оставшиеся настройки, Compose и зависимости после перевода этих команд.
3. Пройти реальные источники, MinIO, Whisper, LLM и пользовательскую выдачу;
   проверить очистку самого Whisper, подготовить выкладку/откат и переключение.
