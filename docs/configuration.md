# Настройки приложения

Главное правило 13.10.2026 передаёт бэкенду все LLM-вызовы и сохранение
итогов после распознавания. Адреса, ключи и таймауты LLM должны перейти
в окружение фонового исполнителя бэкенда. Ниже описано текущее состояние
переходного кода; перенос Settings/Compose ещё предстоит.
[Владельцы операций](processing-ownership.md).

`src/setting/config.py` — источник поддерживаемых настроек и значений по
умолчанию. Pydantic Settings читает `.env` из рабочего каталога процесса;
переменные окружения имеют приоритет над файлом. `get_settings()` кеширует
настройки на время процесса: после изменения окружения нужен перезапуск.

`.env.example` содержит параметры для запуска, без рабочих секретов.
Необязательные параметры можно опустить и получить значение из Settings.
Рабочий `.env` при очистке проекта не перезаписывается. Неизвестные ключи
игнорируются (`extra="ignore"`); это позволяет сохранить старый файл, но
опечатка в имени тоже будет проигнорирована.

## API и Docker Compose

Для API нужны `SPEECH_MS_DATABASE_URL`, параметры входа, MinIO для выдачи
аудио и настройки подготовки запросов модели. Параметры NCC и Whisper в
шаблоне относятся к сохранённым CLI-командам конвейера. Эти команды пока
работают в бэкенде; HTTP-приложение их автоматически не запускает.

Compose передаёт в контейнер только явно перечисленные `environment`.
Для API и миграций используются отдельные DSN:
`AICISTENT_DOCKER_SPEECH_MS_DATABASE_URL` и
`AICISTENT_DOCKER_SPEECH_MS_MIGRATE_DATABASE_URL`. Пароль входит в DSN;
шаблонное `<password>` нужно заменить. Отдельных настроек
`SPEECH_MS_DB_PASSWORD` и `SPEECH_MS_MIGRATE_DB_PASSWORD` приложение не читает.
Образ, порт и сеть — параметры Compose, а не поля Settings.
Порядок запуска описан в [развёртывании](deployment.md).

## Вход, cookies и роли

`SPEECH_AUTH_MODE=open` разрешён только при `APP_ENV=local` или `alpha`.
Режим `keycloak` требует заполнить `SPEECH_KEYCLOAK_ISSUER_URL`,
`SPEECH_KEYCLOAK_JWKS_URL`, `SPEECH_KEYCLOAK_AUDIENCE`,
`SPEECH_KEYCLOAK_URL`, `SPEECH_KEYCLOAK_REALM`,
`SPEECH_KEYCLOAK_CLIENT_ID`, `SPEECH_KEYCLOAK_CLIENT_SECRET` и
`SPEECH_PUBLIC_BASE_URL`. Неполная конфигурация останавливает запуск API.

`SESSION_COOKIE_SECURE=auto` включает Secure везде, кроме local; в local
учитывается схема запроса. `always` включает флаг постоянно, `never` снимает
его и запрещён в prod/production. Эта проверка выполняется при запуске API.
`BACKEND_CORS_ORIGINS` принимает адреса через запятую.
`SPEECH_ROLE_ALIASES_JSON` принимает JSON вида
`{"user":["/speech/readers"]}` и добавляет алиасы к существующему сопоставлению
ролей. Общие параметры `KEYCLOAK_*` из старого приложения не используются.
Scope и PKCE задаёт действующий OIDC-клиент; переменные
`SPEECH_KEYCLOAK_SCOPE`, `SPEECH_KEYCLOAK_RESPONSE_MODE` и
`SPEECH_KEYCLOAK_PKCE_ENABLED` не были подключены к нему.

## Whisper и LLM

Действующий Whisper настраивается только через `SPEECH_WHISPER_*`.
`SPEECH_WHISPER_BASE_URL` — корень OpenAI-совместимого API, обычно с `/v1`.
Клиент отправляет один WAV в `/audio/transcriptions`, запрашивает
`verbose_json` и возвращает DTO текста и сегментов. Пустой адрес вызывает
`WhisperNotConfigured` при сборке клиента.

`SPEECH_WHISPER_TIMEOUT_SECONDS` задаёт общий бюджет HTTP-вызова.
В `infrastructure/transcription/execution.py` разрешена одна попытка:
частично отправленный multipart-запрос не повторяется автоматически.
Внешняя отмена сохраняется как отмена; исчерпание бюджета становится
`TranscriptionError("timeout")`.

Модель и промпт анализа выбирает бэкенд; воркер получает готовый запрос.
`SPEECH_WORKER_API_TOKEN` должен совпадать у обоих процессов.
Ключ `SPEECH_ANALYSIS_LLM_API_KEY` нужен исполнителю запросов: обычный API
через Compose его не получает. Настройки оценки продаж
`SPEECH_QUALITY_LLM_*` остаются для действующей отдельной команды оценки.
Подробности — [служебный контракт и LLM](model-execution.md).

## Очистка 12.10.2026

Удалены неподключённый путь загрузки аудио для черновика заявки, общий
провайдер OpenRouter и его `OPENROUTER_*`/`TRANSCRIPTION_*` настройки,
неиспользуемые фильтры `SPEECH_NCC_PROJECTS`, `SPEECH_NCC_SESSION_DOMAINS`,
`SPEECH_NCC_SESSION_NAUSS`, вспомогательные функции без вызовов и декларации
сроков хранения таблиц старого чата. Политики хранения речи сохранены.

Удалён также `RestCasesSource` и разбор списка кейсов NCC: фабрика уже
отклоняла этот способ, а код оставался только для возможной будущей интеграции.
REST-клиент записи и справочников, источники `sequence`, `reporting_view`
и `local_export` продолжают работать.

Использование проверяется по точкам входа, импортам и тестам. ORM-модели,
миграции, зарегистрированные роутеры и валидаторы не удаляются из-за
отсутствия прямого вызова: их использует соответствующий фреймворк.
Исходный `whisper-backend` сохранён. Отдельного HTTP-маршрута загрузки аудио
в API речи не было; удаление старого сценария не меняет его маршруты.

## Расписание и оценка

Интервалы приёма, дневная доля NCC, ночное окно, размер порции оценки,
`SPEECH_QUALITY_LLM_MODEL` и `SPEECH_QUALITY_LLM_MAX_TOKENS` принадлежат API.
Compose передаёт эти параметры явно. Воркер хранит только свои адрес и ключ
сервера оценки. Служебный токен одинаковый в двух проектах.
[Единый процесс и контракт](worker-runtime.md).
