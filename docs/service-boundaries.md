# Архитектура проектов речи

Решение владельца 11.10.2026: три отдельных репозитория приложения с независимой
сборкой и развёртыванием. Сейчас работаем с бэкендом и воркером; фронтенд отложен.

Главное правило владельца 13.10.2026: воркер получает запись, готовит аудио,
распознаёт и передаёт DTO бэкенду. Бэкенд принимает расшифровку, сам вызывает
LLM, выполняет анализ/оценку и сохраняет итоги. Это цель, к которой ведут
следующие шаги; текущий код ещё содержит переходные обязанности воркера.
[Владельцы операций и гарантии приёма](processing-ownership.md).

## Границы проектов

| Проект | Ответственность | Целевое размещение |
|---|---|---|
| `speech-backend` | API, приём/сохранение расшифровок, бизнес-решения, вызовы LLM, фоновый анализ/оценка и выдача результатов | Kubernetes, CPU |
| `speech-worker` | Получение записей, подготовка аудио, распознавание и доставка результата бэкенду | GPU-сервер, без Kubernetes |
| `speech-frontend` | Пользовательский интерфейс | Kubernetes, CPU |

Решение владельца 12.10.2026: воркер размещаем на GPU-сервере. Сначала
он вызывает существующий контейнер Whisper по HTTP. GigaAM отложен;
локальных моделей, настроек GigaAM и зависимостей PyTorch/CUDA нет. LLM остаётся
отдельным HTTP-сервисом. Бэкенд и фронтенд работают на CPU в Kubernetes.
MinIO и PostgreSQL — сервисы хранения данных; GPU им не нужен.

Уточнение владельца 12.10.2026: MinIO расположен на отдельной машине от
GPU-сервера. В текущем коде воркер скачивает оригинал из MinIO и отправляет
подготовленный WAV в Whisper. На GPU-хосте этот HTTP-вызов будет локальным;
Подробности — в [пути аудио](../../speech-worker/docs/audio-flow.md)
и [целевом пайплайне](../../speech-worker/docs/architecture.md#целевой-пайплайн).

В целевом потоке бэкенд и воркер взаимодействуют через задания и служебный
контракт доставки распознавания. В заданиях передаём идентификаторы и ссылки на данные;
оригинальные аудиозаписи сохраняем в MinIO. Каждый проект должен собираться
без доступа к исходникам соседнего репозитория.

В выделенном воркере сохранена существующая очередь PostgreSQL
`speech_jobs` и фиксацию результата этапа вместе с завершением задания
и постановкой следующего. Схема общая с бэкендом; миграциями владеет
`speech-backend`, требуемая ревизия — `sp_0016_evaluation_jobs`.
Форматы описаны в [контракте разделения 1.1](../../speech-worker/docs/contracts.md).

## Слои бэкенда

| Пакет | Ответственность |
|---|---|
| `src/presentation` | HTTP-роутеры, схемы запросов и ответов, адаптеры входа |
| `src/application` | Сценарии, DTO и порты внешних операций |
| `src/infrastructure` | Реализации портов базы, очереди и внешних сервисов |
| `src/domain` | Бизнес-модели и правила |
| `src/setting` | Pydantic Settings |
| `src/di` | Сборка зависимостей и время жизни ресурсов |

Presentation вызывает application; application применяет domain и использует
порты. Infrastructure реализует эти порты, DI внедряет реализации.
Application не импортирует infrastructure; domain не зависит от других слоёв.
Через границы передаём Pydantic DTO; ORM и HTTP-объекты остаются в адаптерах.

## Запросы к LLM

Бэкенд владеет промптами, выбором LLM, её HTTP-клиентами и вызовами.
Анализ и оценка выполняются надёжным фоновым обработчиком бэкенда на CPU.
Воркер доставляет результат распознавания; исполнение LLM-запросов в него
больше не добавляем. Промпты находятся в ресурсах бэкенда, Dify удалён.
Текущие переходные маршруты и настройки:
[прямое выполнение запросов](model-execution.md).

Основной воркер уже доставляет распознавание бэкенду и не вызывает LLM.
Отдельные переходные LLM-команды ещё сохранены. Следующая задача —
фоновый обработчик анализа/оценки бэкенда, затем удаление прежних потребителей.
[Актуальный план](refactoring-plan.md).

## Состояние перехода

12.10.2026 текущая реализация из `whisper-backend` целиком скопирована в
`speech-backend`: слои, совместимые точки запуска, миграции, тесты и конфигурация.
Git-репозиторий бэкенда, созданный владельцем, сохранён. Окружение `.venv`
создано отдельно; рабочие секреты и кеши исходной папки не копируются.

12.10.2026 фоновые сценарии выделены в `speech-worker`: собственные настройки,
окружение, зависимости, CLI, тесты и Docker-образ. Прежний код внутри бэкенда
сохранён до отдельного решения владельца об удалении. Удалённый сервер
и действующие таймеры пока не переключены.
Переходные точки запуска `app/` удалены из `speech-backend`, сборки UV и
Dockerfile. Реализация в `src/` сохранена; локальные скрипты вызывают её напрямую.
В Compose бэкенда оставлены только API и отдельная команда миграций.
Воркеры, фронтенд, MinIO и фоновые задачи из него исключены; внешняя база
и хранилище подключаются через настройки. Порядок запуска:
[развёртывание бэкенда](deployment.md).
Исходный `whisper-backend` и его окружение сохранены без изменений. Разделение
выполняем законченными сценариями, сохраняя проверенные бизнес-правила.

Не возвращаем обезличивание текста. Оценка продаж предназначена для Телфина;
NCC в неё не входит. Эти правила сохраняем при разделении проектов.
