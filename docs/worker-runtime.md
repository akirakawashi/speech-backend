# Запуск приёма, распознавания и CPU-обработки

Состояние 14.10.2026: `speech-process` бэкенда принимает метаданные и ставит
задания по расписанию, последовательно выполняет анализ/оценку и независимо
планирует оценку. `speech-worker` на GPU-сервере последовательно получает
аудио, вызывает Whisper и доставляет DTO распознавания.
[Правила приёма, контракт и оставшиеся задачи](intake-ownership.md).

## Два процесса

В `speech-backend`:

```bash
uv run --locked speech-process
```

В `speech-worker`:

```bash
uv run --locked speech-worker
```

Приём не требует GPU или ffmpeg. Списки звонков получает бэкенд через адаптеры
источников; воркер скачивает только записи готовых заданий. MinIO находится
на отдельной машине, Whisper работает в своём существующем контейнере.

| Действие бэкенда | Сохраняемое расписание |
| --- | --- |
| Телесейлз (`ncc`) | Раз в 15 минут; днём сразу доля 0.5, остальные с 19:00; ночью всё сразу |
| Телфин | Раз в час, ночью 19:00–07:00 по Москве; приоритет 20 |
| Оценка | Независимая постановка раз в 15 минут, порция 100, только готовый Телфин |

Приоритеты: NCC 0/10, Телфин 20, история 100. При перезапуске выполняется один
догон; регистрация повторных суток не меняет принятое задание. Долгий источник
не блокирует другой источник, оценку или модельную обработку.

## Режимы

```bash
uv run --locked speech-process --sources ncc
uv run --locked speech-process --sources '' --no-schedule
uv run --locked speech-process --once
uv run --locked speech-analyze --once
```

`--sources` бэкенда выбирает автоматический приём; пустая строка отключает его.
`--no-schedule` отключает только постановку оценки. `--once` не запускает приём
метаданных и выполняет не больше одного задания; `speech-analyze` выполняет
только анализ без приёма. Флаги `--stages` и `--lanes` ограничивают CPU-задания.

У воркера остаются `--stages ingest,transcribe`, `--lanes daily,backfill`,
`--once`. Он всегда работает с очередью: прежние `--sources`/`--queue-only`
удалены. SIGTERM прекращает новые захваты; текущая работа заканчивается,
пулы закрываются. CPU-процесс отменяет незавершённые опросы метаданных;
день, не дошедший до commit, повторяется при следующем запуске.

Ручной приём и история находятся в бэкенде: `speech-ingest`, `speech-backfill`.
Ручная очередь оценки:

```bash
uv run --locked speech-evaluate --all --limit 100 --enqueue --apply
```

Без `--apply` подсчитывается охват. Постановка не требует модели или служебного ключа.
[CPU-обработка и атомарность](evaluation-processing.md).

## Служебный HTTP

- `/internal/v1/ingest/prepare` — техническая команда конкретному живому захвату.
- `/internal/v1/ingest/resolve` — решение бэкенда по фактам скачивания.
- `/internal/v1/transcription-results` — атомарное сохранение ASR, завершение и анализ в очередь.

Везде Bearer-токен и DTO версии 1.0. Старые `worker-plan`, `model-requests`,
`quality-steps`, `quality-jobs` удалены. Модельные запросы воркеру не передаются.
[Доставка ASR, повторы и буфер](transcription-delivery.md).

## Переключение

Сервер пока не переключён. Нужны совместимые API/CPU-процесс/воркер, схема
`sp_0017_analysis_storage`, одинаковый служебный токен и сетевой доступ.
Reporting и секреты API списков звонков теперь настраиваются в бэкенде;
воркеру нужны только скачивание, MinIO, Whisper и служебный API.

Перед выпуском остановить прежние исполнители/таймеры этой базы и дождаться
активных заданий. Проверить резервную копию, порядок отката и живое прохождение
звонка. Затем согласованно запустить новые процессы. Одна ревизия базы сама по
себе не гарантирует совместимость HTTP. Новых миграций для переноса приёма нет.
Рабочие `.env`, исходные проекты и внешняя инфраструктура сохранены.
