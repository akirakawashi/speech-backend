# Единый приём и CPU-обработка

Состояние 13.10.2026: одна команда `speech-worker` на GPU-сервере исполняет
приём и ASR; одна команда `speech-process` проекта бэкенда на CPU выполняет
анализ/оценку и независимо ставит оценку по расписанию.
LLM-код, модельные настройки и его отдельные команды из воркера удалены.
[Границы и совместимость](llm-ownership.md).

## Запуск

В самостоятельном `speech-worker`:

```bash
uv run --locked speech-worker
```

В `speech-backend`:

```bash
uv run --locked speech-process
```

Воркер последовательно исполняет ingest/transcribe. Независимые циклы
NCC/Телфина получают планы у бэкенда и не блокируют очередь.
`--queue-only` отключает автоматический приём; `--sources ncc` выбирает
источник. `--once` исполняет не больше одного доступного задания без приёма.
При SIGTERM приём прекращается сразу, текущая работа заканчивается.

CPU-процесс последовательно исполняет analyze/evaluate. Отдельная задача
планировщика продолжает постановку оценки во время ожидания LLM.
`--stages` выбирает виды, `--no-schedule` отключает постановку,
`--once` выполняет не больше одного задания. Первый режим — одна реплика.
[Аренда, атомарность и остановка](evaluation-processing.md).

## Расписание и приоритеты

Параметры определяет `CollectionSchedule` в бэкенде. Приём NCC — каждые
900 секунд; Телфин — каждый час ночью по Москве, 19:00–07:00.
Днём половина новых NCC идёт сразу, остальное — с 19:00; ночью всё сразу.
Приоритеты сохранены: свежие NCC 0, отложенные 10, Телфин 20, история 100.
`not_before` сохраняется в задании; уже накопленный Телфин обрабатывается
и днём после более срочных NCC.

Оценка ставится независимо для готового Телфина: интервал по умолчанию
900 секунд, порция 100, не повторять неудавшиеся оценки автоматически.
Один CPU-процесс сохраняет прежние правила выбора/дедупликации;
модельные задания остаются последовательными. Приоритет оценки не ниже 30
и наследует полосу/приоритет анализа.

Интервалы, доля, часы и порция задаются настройками бэкенда:
`SPEECH_NCC_INGEST_INTERVAL_SECONDS`, `SPEECH_TELPHIN_INGEST_INTERVAL_SECONDS`,
`SPEECH_NCC_IMMEDIATE_SHARE`, `SPEECH_NIGHT_FROM`, `SPEECH_NIGHT_UNTIL`,
`SPEECH_QUALITY_INTERVAL_SECONDS`, `SPEECH_QUALITY_BATCH_LIMIT`.
Остальные правила приёма/истории/хранения ещё завершают перенос из воркера:
[план](refactoring-plan.md).

## Служебный контракт

`POST /internal/v1/worker-plan` принимает `MaintenanceRequest` только с
действием ncc/telphin. Возвращает срок и готовый `CatchUpCommand`.
Используется версия DTO 1.0 и совпадающий служебный Bearer-токен.
`evaluation: null` сохранён для совместимости; непустая оценка не принимается
воркером. Свойство модели или её ключ в этот контракт не входит.

`POST /internal/v1/transcription-results` принимает подготовленный ASR,
проверяет nonce/аренду/вход, сохраняет транскрипт и ставит analyze одним commit.
Воркер получает квитанцию и не делает независимый store/complete.
[Доставка и восстановление](transcription-delivery.md).

Маршруты `model-requests`, `quality-steps`, `quality-jobs` удалены.
Ручная постановка оценки выполняется локально через команду бэкенда:

```bash
uv run --locked speech-evaluate --all --limit 100 --enqueue --apply
```

Без `--apply` подсчитывается охват. Ключ и адрес LLM для постановки не нужны.

## Порядок переключения

Сервер пока не переключён. Перед выпуском остановить прежние исполнители
и таймеры этой базы и дождаться активных заданий. Проверить API, схему
`sp_0016_evaluation_jobs`, токен и доступ к источникам, MinIO и Whisper.
Затем запустить один воркер ASR и один CPU-процесс бэкенда, проверить новый
звонок и независимую оценку Телфина. Старый приём и новые процессы не должны
одновременно обслуживать одну базу.

Новых миграций при очистке LLM не добавлялось. Автоматическая миграция при
старте отсутствует. Рабочие `.env`, исходные проекты и внешняя инфраструктура
сохранены. Развёртывание готовится отдельным шагом:
[бэкенд](deployment.md), [воркер](../../speech-worker/docs/deployment.md).
