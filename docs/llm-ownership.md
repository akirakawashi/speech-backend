# Владение LLM после очистки воркера

Выполнено 13.10.2026. `speech-worker` получает записи, готовит аудио,
вызывает Whisper и доставляет результат распознавания. Промпты, модельные
клиенты, разбор текста, скрипт продаж и запись анализа/оценки находятся
в `speech-backend`.

Миграции, рабочие `.env`, исходные проекты и действующий сервер не менялись.
Требуемая схема остаётся `sp_0016_evaluation_jobs`. Батчи, CUDA/PyTorch,
GigaAM и новые внешние сервисы не добавлены.

## Команды и потребители

Команды причин, классификатора и сравнения уже имели реализации в бэкенде.
Повторное копирование не потребовалось. Проверены CLI, DI, локальные
подготовители, порты, ресурсы промптов и тесты; команды зарегистрированы
в сборке бэкенда. Runtime-импорты соседнего проекта отсутствуют.

| Команда бэкенда | Назначение |
|---|---|
| `speech-process` | Последовательные `analyze`/`evaluate` и независимая постановка оценки |
| `speech-analyze` | Сохранённый отдельный режим анализа |
| `speech-evaluate --enqueue` | Проверка охвата и ручная постановка оценки в общую очередь |
| `speech-evaluate` | Сохранённая ручная пакетная оценка; модель и запись выполняет бэкенд |
| `speech-reanalyze` | Повторная постановка готовых разговоров на анализ |
| `speech-fill-reasons` | Заполнение причин обращения с проверкой кода по справочнику |
| `speech-classifier-backfill` | Связь звонков с классификацией из представлений NCC |
| `speech-seed-classifier`, `speech-seed-call-reasons` | Начальные справочники |
| `speech-compare-models` | Сравнение кандидата/контроля с сохранённым результатом и выбором оператора |

После `uv sync --locked` все команды доступны через `uv run --locked`
и поддерживают `--help`. Старые точки `python -m src.presentation.cli.*`
в бэкенде сохранены.

Пример ручной постановки оценки:

```bash
uv run --locked speech-evaluate --all --limit 100 --enqueue
uv run --locked speech-evaluate --all --limit 100 --enqueue --apply
uv run --locked speech-process
```

Первый вызов считает кандидатов, второй ставит задания, третий исполняет их.
`--force`, `--skip-failed`, один звонок, период и `--drop-stale` сохранены.
Без `--enqueue` флаг `--apply` по-прежнему означает непосредственную ручную
оценку; семантика прежней команды бэкенда не заменена молча.
Для переноса бывшего вызова воркера `speech-evaluate --apply` добавить
`--enqueue` и запускать команду в бэкенде.

Постановка использует `WorkerMaintenanceService.enqueue` локально, проверяет
схему, закрывает пул в `finally` и не требует адреса LLM или служебного токена.
При повторе активное задание дедуплицируется прежним SQL-репозиторием.

## Локальная подготовка и сравнение

`build_analysis_client` внедряет `LocalModelRequestPreparer`. Все четыре
сохранённых сценария (`analysis`, `reason`, `free_classification`,
`operator_compare`) готовят DTO и промпт локально. Сохранены производственный
и кандидатный профили, выбор отдельной модели свободной классификации,
лимиты и проверки входа. Основной анализ по-прежнему разбирает обычный путь,
`ai_path`, тональность, роли, резюме и причины по прежним правилам.
Новое поведение классификации не вводилось.

Сравнение вызывает `AnalysisExecutionService` напрямую. Оно не создаёт
фиктивное задание, `StageDeps`, временный каталог или ресурсы ffmpeg.
`PostgresComparisonRepository.analysis_input` читает один согласованный DTO
в короткой `REPEATABLE READ`; соединение закрывается до HTTP.
Кандидат и контроль получают один снимок, даже если разговор изменился
между запросами. Сравнение возвращает отчёт и не записывает вычисленные
роли, анализ, оценку или состояние задания.

Сохранённая многошаговая команда оценки использует локальный
`QualityPreparationService.prepare`; для вычисления ей больше не передают
служебный токен. Расчёт разделяется с CPU-обработчиком через `compute_quality`.

## Что удалено

В воркере удалены обработчики `analyze`/`evaluate`, клиенты LLM и подготовки
запросов, бизнес-DTO и порты этих сценариев, интерпретаторы текста, скрипт
продаж, адаптеры записи оценок/анализа, начальные справочники и их команды.
Удалены `SPEECH_ANALYSIS_LLM_*`/`SPEECH_QUALITY_LLM_*` из Settings и шаблона.
Рабочие `.env` сохранены: старые ключи игнорируются `extra="ignore"`.

Старый `TranscribeHandler.store` больше не пишет SQL и отказывает при вызове.
Из воркера удалены SQL записи транскрипта и соответствующий порт; результаты
распознавания принимает только бэкенд. Сохранены подготовка аудио, чтение
метаданных, буфер неподтверждённого DTO, повтор доставки и очистка файлов.

В бэкенде удалены служебные маршруты:

- `POST /internal/v1/model-requests`;
- `POST /internal/v1/quality-steps`;
- `POST /internal/v1/quality-jobs`.

Они возвращают 404, включая запрос с правильным служебным ключом.
Маршруты приёма ASR и `worker-plan` сохранены. План приёма поддерживает
только `ncc`/`telphin`; оценку планирует CPU-процесс. DTO приёма сохраняет
совместимый `evaluation: null` в контракте 1.0. Непустая команда оценки
в ответе управления отклоняется воркером. Безопасная обработка ошибок
валидации вынесена в `presentation/http/validation.py` и сохраняет защиту ASR.

## Проверки и оставшаяся работа

Проверки на временной PostgreSQL: 204 целевые проверки бэкенда, полный
бэкенд — 1496 passed, 21 skipped; полный воркер — 547 passed.
Пропуски относятся к отсутствующим внешним скриптам инфраструктуры.
Число тестов воркера уменьшилось за счёт удаления дублей анализа/оценки и
проверок закрытого HTTP-подхода. SQL-запись ASR проверяется в бэкенде;
все проверки распознавания, доставки, аренды, повторов, логов и очистки сохранены.
Дополнительно проверены отсутствие старых маршрутов, ограничения runtime,
локальные промпты/ключи, общий снимок сравнения, отсутствие соединения
во время HTTP и ручная постановка без LLM/токена.

Ruff, форматирование, строгий mypy и проверка lock-файлов прошли.
UV собрал wheel и исходный архив обоих проектов. Установленные wheel
проверены вне исходников: девять команд бэкенда и пять команд воркера
поддерживают `--help`; в архиве воркера отсутствуют удалённые LLM-модули.
Настоящий CLI из wheel на отдельной PostgreSQL выполнил подсчёт,
постановку и повтор без дубля, без адреса модели/служебного токена.
Собраны образы API, общего CPU-процесса, отдельного анализа и воркера.
Одноразовые проверки без сети подтвердили пользователя 10001 и состав
пакетов: воркер с ffmpeg без LLM/PyTorch; CPU-процесс без ffmpeg/PyTorch.

убрать его дубли получения и распознавания после замены потребителей,
подготовить переключение. Метаданные классификации из NCC и действующие
технические команды приёма в воркере сохранены.
